# 原生界面性能与边界修复

> 点击 ENTER SYSTEM 后首次停顿的专项修复见[入场修复记录](ENTER-SYSTEM.md)：完整绘制管线在入口可用前准备，不再在首个真实画面中同步链接后处理着色器。

## 修复范围

保留原 GLB、相机轨迹、波浪与归位规则、原始画质默认值。没有默认切换性能画质，没有降低 AO/阴影/景深/透明度分辨率。测试过的上下文 MSAA 改动未得到可靠收益，已恢复原值。

1. 目录按修订一次性建立列索引与位置索引。指针/连续选档不再反复 flatMap 全目录。
2. 解密标记使用持久 SVG 节点；不可见时不再计算投影与重建几何。投影复用已更新的模型矩阵。
3. 只有变化的详情样式、状态文字才写入 DOM；安装进度保留取消按钮，避免丢失焦点。
4. 原生拖动仍遍历真实经过的格子、保留原波浪/归位，但同帧中间文字只更新一次。
5. 行肩部变形与列强度仅在同一模拟帧内缓存。数值测试覆盖大坐标重定位和半行样本，与原公式及 Float32 值完全相等。
6. 已结束的归位副本进入最多 6 个的资源池，复用独立标签纹理与材质；活动副本不截断、不共享状态，卸载时全部释放。
7. 着色器在资源就绪阶段准备；等待有取消和超时，保留编译错误检查。
8. GPU 提交采用零等待 fence 检查，最多一帧在途。GPU 忙时不继续堆积画面或覆盖未提交的上传范围；界面输入、状态与时钟继续响应，拾取仍基于最近提交的几何。
9. 3D 绘制帧率与 UI 回调帧率分别记录，不能把较高 UI 帧率冒充 GPU 绘制 FPS。完整场景诊断仅显式启用，避免普通交互周期性遍历模型。
10. 启动遮罩、移动端入口、字幕注册表、监听器、轮询与帧回调均纳入清理；反复关闭重开没有重复入口或画布。

## 可复查测量

- [确定性目录微基准](../.reference/catalog-microbench.ts) / [结果](../.reference/catalog-benchmark.json)：757 条记录、150,000 次查找，5 轮中旧实现约 3.46–3.54 秒，新索引约 3.46–4.65 毫秒，校验和完全相同。这只是目录查找微基准，不是应用 FPS 提升倍数。
- [预热对照脚本](../.reference/controlled-performance.mjs)：相同 1920×1080、DPR 1、NVIDIA RTX 5060 Laptop、原始画质。旧/新两种顺序均测量，不能只挑有利的一次。
- 一组稳定详情样本的布局计数从 1301 次/638 个 UI 帧降为 29 次/465 个 UI 帧，约 2.04 → 0.062 次/帧。不同轮次 GPU 负载和绘制 FPS 仍有明显波动，未把跨天帧率差异当作代码收益。
- [GPU 与 UI 调度分离](../.reference/native-gpu-profile.mjs) / [结果](../.reference/native-gpu-profile.json)：使用真实 GPU 计时查询。GPU 忙时，提交背压后的详情 UI 回调 P95 为约 4.3 ms；实际 GPU 绘制时间仍单独报告，未宣称 200+ FPS 的三维渲染。
- 上述方法保留画质，目标是减少已定位的 CPU/布局/分配和 GPU 排队停顿。GPU 满载或其他程序竞争资源时，绝不保证所有设备保持固定绘制 FPS。

## 原生管理边界

账号认证、模组/内容市场、整合包预检与导入已接入原弹窗，不需要跳转旧管理页。每个操作仍是独立 capability。

- 微软：合法公共客户端 ID、真正设备码/完成接口、退避提示、单流程取消；不暴露 device_code 或 access_token。过期/拒绝不会标成成功。
- 外置认证：真实服务端地址与用户名/密码请求，密码提交后清空，不持久化到面板。
- 模组：操作绑定选中实例；原版实例不提供仅支持加载器的构建；改变查询/来源清除旧结果；更新只提交服务端核验的 updateId，删除/更新须确认。
- 整合包：输入本机完整归档路径，先预检，再确认导入；改变路径/名称使旧预检失效。浏览器没有 File.path，未伪造该字段。
- 导入与安装仅在实际任务 succeeded 后显示完成。关闭面板取消界面等待，不伪称取消后台任务；重开刷新任务，可明确取消。
- 原后端未提供整合包导出协议，本轮没有伪造一个导出按钮或声称支持不存在的格式。
