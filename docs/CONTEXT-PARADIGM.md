# Context 范式在 Rhine Launcher 中的边界

依据论文 [A Programming Paradigm for Spatiotemporal Composability, arXiv:2608.25512v1](https://arxiv.org/abs/2608.25512v1) 与本机 DSH 0.2.1-rc.3 的实际源码。已阅读重点为 §1–3（定义）、§5（Cordis/声明式加载/HMR实现）、§6（边界、沙箱、粒度），不是对全部形式证明声称机器验证。

## 1. 用户要求的粒度

每个公开动作一个描述文件和一个 Cordis fiber；页面、主题切换、运行库下载、客户端安装、认证provider的开始/完成/刷新均独立。目录和发行包是可打包的集合，不是运行时“大插件”。这对应论文 §6.5 的细粒度组件与独立集成绑定。

## 2. 三项机制

- **可撤销副作用**（§3.1 / §5.1.1）：在创建处记录清理逆操作，而不是各处创建后依赖一个大 shutdown。注册能力、监听器、定时器、fetch controller、WebGL实例、子进程归所属 fiber；卸载按依赖逆序收回。
- **响应式依赖**（§3.2 / §5.1.2–3）：未提供依赖就是 blocked；依赖消失则先清理依赖方，恢复后重新加载。不能吞异常后显示空列表当成功；实例启动/安装只有单独动作自己的依赖被满足才可执行。
- **统一上下文**（§3.3 / §5.1.4）：业务调用通过声明过的 capability，旧 ctx.* 只是转发投影；不能从 ctx.root/features 任意绕过声明。一个真实 Cordis scope 对应一个功能，不是布尔表假装卸载。

## 3. 声明式配置与替换

稳定 id 对应一个组件实例（§5.2.1）。配置 reconcile 仅重载有语义变更的节点及必需下游，不影响无关实例/页面。更新失败必须还原旧实现和旧依赖图（§5.2.2 算法10）。普通 Node ESM 没有公开缓存驱逐 API，因此不能把给URL加时间戳说成完整依赖树 HMR；宿主只承诺显式单功能替换与事务回滚，开发构建用 Vite/tsx 重建。

## 4. 正确的系统边界

论文 §6.1 明确 acquisition（获取资源）与 emission（向外输出）不是同一保证：
- 可撤销：能力绑定、组件渲染/事件、未提交 staging、运行时持有的临时下载/文件句柄。
- 已提交持久数据：下载验证完的游戏、模组、用户世界和账号配置。停用插件**不会删除**它们。
- 外部不可逆：已经发送的认证请求、玩家已经看到的游戏画面。只能取消后续请求或做业务补偿，不能宣称已撤销远端效果。

导入/更新先校验、暂存、原子提交；取消时由创建资源的操作清理它自己保留的私有 staging，不能撤销其他并行插件提交的数据。

## 5. 直接复用 DSH

- @deepseek-ai/cordis@4.0.5：ctx.plugin/fiber/effect/provide/inject 真实运行时。
- @deepseek-ai/dsh-atomic-write@0.2.1-rc.3：writeFileAtomic + withFileLock，Windows重命名重试和权限保留，不复制一份声称等价代码。
- 参考 DSH vendor/loader 的稳定 entry id、反向配置同步、依赖作用域生命周期；参考 client/modules 的模块到达与实例化分离。

对新增协议/界面使用本项目的单功能 descriptor 约束：论文允许组件多个提供项，而本项目按用户要求限定一个。

## 6. 安全声明

论文 §6.3 明确：Context 访问约束不等于不可信代码沙箱。可信插件仍能通过宿主语言node:fs做事；未经审核的任意第三方源码必须另用隔离进程/沙箱。本项目目前只自动加载内置/用户明确指定的可信插件目录，不承诺恶意插件隔离。

## 7. 验收

真实fiber相互独立；未声明依赖包括投影绕过失败；provider撤销/替换影响正确下游；异步获取中卸载能取消并等清理；反复启用/禁用无监听器/renderer残留；配置有序/乱序最终状态一致；坏更新恢复旧实现；已提交文件在卸载后保留。具体断言见 plugin-api/test 与 core/server/web 的集成测试。
